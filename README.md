# CFG Ambiguity Checker (Brute Force Engine)

An automated, cross-platform Progressive Web Application (PWA) and high-performance FastAPI backend designed to dynamically evaluate Context-Free Grammars (CFGs) for ambiguity using bounded-depth brute-force parse tree derivation.

## 🎯 Theoretical Background (TOC)
In the Theory of Computation:
1. **Context-Free Grammar (CFG):** Formally defined as a 4-tuple $G = (V, \Sigma, R, S)$, where $V$ is a finite set of non-terminal symbols, $\Sigma$ is a finite set of terminal symbols disjoint from $V$, $R$ is a finite relation mapping $V \to (V \cup \Sigma)^*$, and $S \in V$ is the start symbol.
2. **Ambiguity:** A CFG $G$ is called **ambiguous** if there exists at least one string $w \in L(G)$ that admits:
   - Two or more distinct **leftmost derivations**, OR
   - Two or more distinct **rightmost derivations**, OR
   - Two or more distinct **parse trees**.
3. **Earley Parsing Algorithm:** An efficient $O(n^3)$ dynamic programming parsing chart algorithm ($O(n^2)$ for unambiguous grammars, $O(n)$ for LR/LL) that computes State Sets $S_0, S_1, \dots, S_n$ representing all partial parse trees through three fundamental operations:
   - **Predictor:** Expands non-terminals at the dot position into newly initialized candidate productions.
   - **Scanner:** Advances the dot across matching terminal tokens consumed from the input.
   - **Completer:** Advances the dot in ancestor states when a sub-derivation finishes.
4. **Decidability Note:** The general problem of determining whether an arbitrary CFG is ambiguous is **undecidable** (Post's Correspondence Problem reduction). However, for any specific target string $w$, determining whether $w$ has multiple distinct parse trees is decidable. This system evaluates bounded-depth derivation trees up to $\text{max\_depth} = \max(2|w| + 6, 14)$ to detect string-level ambiguity.

## 🚀 Getting Started

### 1. Backend Setup & Startup
Navigate into the `backend` directory:
```bash
cd backend
python -m pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```
The FastAPI documentation and OpenAPI schema will be accessible at:
- Swagger UI: [http://localhost:8000/docs](http://localhost:8000/docs)
- Health check: [http://localhost:8000/api/health](http://localhost:8000/api/health)

### 2. Frontend Setup & Startup
Serve the `frontend` directory using any HTTP server:
```bash
cd frontend
python -m http.server 3000
```
Open your browser at [http://localhost:3000](http://localhost:3000).

## 🧪 Verification Test Cases

### Test Case 1: Classical Ambiguous Arithmetic Grammar
- **Start Symbol:** `S`
- **Grammar Rule:** `S -> S + S | a`
- **Target String:** `a+a+a`
- **Expected Result:**
  - Verdict: **AMBIGUOUS CFG** (`is_ambiguous: true`)
  - Parse Tree Count: 2
  - **Tree 1:** Associates as `(a + a) + a`
  - **Tree 2:** Associates as `a + (a + a)`

### Test Case 2: Unambiguous Matched Bracket / Epsilon Grammar
- **Start Symbol:** `S`
- **Grammar Rule:** `S -> a S b | ε`
- **Target String:** `aabb`
- **Expected Result:**
  - Verdict: **UNAMBIGUOUS / SINGLE TREE** (`is_ambiguous: false`)
  - Parse Tree Count: 1
  - Derivation: $S \Rightarrow aSb \Rightarrow aaSbb \Rightarrow aabb$

### Test Case 3: Non-Derivable String
- **Start Symbol:** `S`
- **Grammar Rule:** `S -> a S b | ε`
- **Target String:** `aab`
- **Expected Result:**
  - Verdict: **NOT IN LANGUAGE / NO TREE** (`tree_count: 0`)
  - Explanation: String cannot be generated by the grammar rules within bounded depth.
